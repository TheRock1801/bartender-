## What changed from the Aria & Jansen app (all 2026-10-22, from the mood board)

- **No sign-in step, no flavour prefs, no favourite, no guests table.** The name is typed on the "Your Order" page and remembered on the phone (`rj_guest_name`); "your drinks" are found by `device_id` only (`GET /api/orders/mine?device_id=`). The `guests` routes/table/migration are gone.
- **Collect or deliver (new):** `orders.fulfilment` (`collect` default | `deliver`) + `orders.table_no` (required when delivering, nulled otherwise), validated in `resolveFulfilment()` in `api/index.js`, for guest and verbal orders alike. Remembered on the phone (`rj_fulfilment`, `rj_table`).
- **Order numbers (new):** `orders.order_no` is a Postgres `serial` (the memory store counts from 1); shown as `#14` on both screens. The bar fetches `?all=1` every poll so its Delivered filter works.
- **Tabs: Spirits, Cocktails, Beer & Wine, Non-alcoholic** (`CATEGORIES`). Hot Drinks and the sugar logic are gone. Seed menu is in `lib/store.js` and `supabase_schema.sql`: Whiskey, Bourbon, Gin, Vodka, Rum, Brandy, Cognac / Espresso Martini, Aperol Spritz, Whiskey Sour / Beer, Red, White, Sparkling wine / Lemonade, Orange juice, Pineapple juice, Cranberry juice, Sparkling water (the Non-alcoholic "Juice" was one Add-only drink with "Orange, pineapple or cranberry" as its description and no way to pick, so it was split into three drinks on 2026-10-22; `supabase_juice_flavours.sql` does the swap on a database that had already been reset). The cocktails are placeholders Rocky hasn't confirmed. The "Nothing to pay" footer line was removed the same day at Rocky's request.
- **Mixers** (`MIXERS`): Coke, Coke Zero, Lemonade, Dry Ginger Ale, Soda Water, Tonic Water, Ginger Beer, Orange/Pineapple/Cranberry juice (shown under one "Juice" row with the three flavour chips ALWAYS visible inside the row, `isJuice()` in `src/cart.ts`; originally the chips only appeared after tapping the row and Rocky read that as "3 options but nowhere to click", fixed 2026-10-22), On the rocks, plus **Other**: the guest types up to 40 chars, stored in `order_items.mixer` as `Other: <text>` (`OTHER_MIXER_RE`, `isValidMixer()`); `itemLabel()` renders it as "Gin & lime and soda". Coke Zero replaces the old fat/skinny pref; `resolveMixer`/`MIXER_VARIANTS` are gone, bartenders use the same list.
- **Pour is Regular / Light only** (Rocky, 2026-10-22: "only make a light option instead of light + stiff"). `STRENGTHS = ['light']` in `lib/store.js`, spirits only, server-validated; a "Pour" row at the bottom of the mixer page. `stiff` is rejected. The `order_items.strength` column is unchanged (text), only the allowed value shrank.
- **Mixer picking is a full-screen page** (`MixerSheet` in `src/DrinkRows.tsx`): back arrow, big glass, spirit name, "Choose your mixer", radio rows, then "Add to order" fixed at the bottom. Tapping "Choose" on a spirit opens it; non-spirits are Add then − n +.
- **"Your Order" is a full-screen page** (`OrderSheet` in `src/GuestApp.tsx`): florals, script heading, lines with − n +, "How would you like your drink?" two cards, table number, name, "Place order — it's on us!". The bottom bar on the menu is one button, "View your order · n drinks".
- **Bar queue restyled** (`Queue`/`OrderRow` in `src/BarApp.tsx`): filter tabs All orders / New / Preparing / Made with counts, rows of `#no + time | glass | name + drinks | Deliver Table 4 or Collect at bar | status pill` (sand New, terracotta Preparing, olive Made). Tap a row to expand the items and the actions. The mood board's "Preparing" dropdown became explicit buttons on purpose (no mis-taps).
- **No bartender names, no claims (Rocky, 2026-10-22: "remove the bartender option").** The bar is PIN → queue, nothing else; `BARTENDERS`, the "who's pouring?" screen and `claimed_by` handling are gone. `PATCH /api/bar/orders/:id` takes only `{action}`: `start` (New → Preparing), `made` (→ done), `putback` (Preparing → New), `cancel`, `reopen` (→ Preparing). Verbal orders get `placed_by: 'Bar'`. The `orders.claimed_by` column still exists, always null.
- **One finishing step, "Made it" (Rocky, 2026-10-22: "there shouldnt be a made it and then delivered it option, should be purely made it").** Status flow is `new → making → delivered`; the `ready` status is never set any more (kept in the DB check and `OPEN_STATUSES` for safety, and the UI renders it like `delivered` if an old row has it). `delivered` reads as "Made" on the bar and "Made, come grab it at the bar" / "Made, on its way to table N" for the guest; a made order stays under the guest's "Your drinks" for 5 minutes after `updated_at`, then drops to "Earlier".
- localStorage keys are `rj_*` (device id, guest name, fulfilment, table, bar PIN).

## Data model (Supabase)

`supabase_riley_jasmine_reset.sql` is the one to run on the existing project (see above); it is idempotent in the sense that running it again just resets again. `supabase_schema.sql` is the same end state built from scratch, only for a brand-new project. Tables: drinks (incl. instructions), orders (incl. order_no serial, fulfilment, table_no), order_items (incl. mixer, strength), settings. The old `guests` table is dropped by the reset. No migration runner; Rocky pastes SQL into the Supabase editor. Any new column needs a new file and must be run before the deploy that uses it.

## Product rules carried over (don't undo)

- Deliberately minimal: no payments, no accounts, no email, no per-guest order cap.
- A spirit without a mixer is rejected server-side; a mixer on a non-spirit is rejected. Lines with the same drink + mixer + pour merge.
- Verbal orders ignore `ordering_open` and availability so the bar can always record what it's making.
- Tapping a drink name (Menu tab, or inside an expanded order) opens the recipe sheet: instructions, ordered-tonight tally, mark run out, remove (confirm step; past orders keep the name).
- Optional chime on new orders (needs a tap first).

Fonts (Google): **Italianno** `script` for "Riley & Jasmine", "the bar", "Your Order"; **Cormorant Garamond** `display` for drink names and headings (Title Case, no lowercase-with-full-stop convention any more); **Jost** body at weight 300, `spaced` (0.28em caps) for tabs/"DRINKS ARE ON US"/date, `label` (0.2em caps) for small headings. Classes in `src/index.css`: `btn-primary` (terracotta), `btn-dark`, `btn-soft` (thin outline, the "Choose" button), `btn-ghost`, `card` (ivory, rounded-2xl, no border), `row`, `divider`, `input`, `pill`, `ring-radio`, `step-btn`, `fade-up`. Faint paper grain. Reduced motion respected. No shadows.

**Artwork is all inline SVG in `src/art.tsx` (since 2026-10-22).** The first version used literal crops of the mood board JPEG (low-res, with the board's own cream baked in), and Rocky said they looked "stuck on" and "not clear cut", so they were replaced with vectors in one style: thin cocoa line, soft amber/terracotta fills, transparent background. `Glass name=...` picks an icon by keyword (`RULES` in `art.tsx`, first match wins, specific names before general: whiskey sour before whiskey, sparkling wine before wine, each juice flavour before plain juice; unknown names get the tumbler). There is a dedicated icon for every seeded drink: tumbler, bourbon, gin balloon, vodka highball, rum with mint, snifter (brandy/cognac), espresso martini, spritz, sour coupe, pint, red/white wine, flute, lemonade, orange/pineapple/cranberry juice, sparkling water, plus soft drink and coffee for anything the bar adds later. `HeaderArt` is the board's table spread redrawn (bottle, candles, bouquet in a vase, coupe, wine glass, flute, cake slice). `public/art/` now holds only `mood-board.jpg` (the brief). To eyeball changes without a browser: bundle a tiny entry with esbuild (`--format=cjs --jsx=automatic`) that `renderToStaticMarkup`s the components, then rasterise with `@resvg/resvg-js` installed in the scratchpad, as done on 2026-10-22.
